依赖库版本体检

对照仓库的 pyproject.toml（声明下限）、uv.lock（实际锁定并测试过的版本）与 PyPI 当前最新版，逐一检查本书用到的核心 Agent 相关库是否过时。

结论先说

按仓库自带的 uv.lock 执行 uv sync 得到的环境基本是新鲜的、能正常运行的。真正的风险在于：pyproject.toml 里写的版本下限（如 fastmcp>=0.1.0）非常宽松，如果绕开 uv.lock 直接用 pip install -e . 解析依赖，可能会装到跨越了大版本、接口已发生破坏性变化的最新版。

三个值得注意的细节

  • FastMCP 其实是"影子依赖"。 代码里真正 import 的是 mcp.server.fastmcp.FastMCP——MCP 官方 SDK 内置的低阶实现，接口稳定、随 mcp 包一起维护。pyproject.toml 里单独声明的 fastmcp（Jlowin 维护的独立项目，已经出到 v4，和内置版 API 早已分叉）在 scratch_agents 和 notebooks 里没有任何 import fastmcp，属于声明了但没用上的依赖，可以放心忽略其版本跨度，也可以考虑从 pyproject.toml 里移除以减少混淆。
  • Anthropic SDK 已经发布 1.0。 0.x → 1.x 是一次正式的大版本升级，官方发过迁移说明。仓库锁定的 0.84.0 目前仍可用，但如果要手动升级到 1.x，应先过一遍 Anthropic 官方的迁移指南再改代码，不要只改版本号。
  • chromadb 的 Client() 便捷用法。 第 6 章示例和 scratch_agents/memory/long_term.py 都用 chromadb.Client() 创建一个内存态客户端——这是 chromadb 1.x 里仍受支持的写法，正常可用；如果要换成进程重启后数据不丢的持久化存储，需要显式改成 chromadb.PersistentClient(path=...)，本书目前的教学场景（单次实验/演示）用内存态已经足够。
给自己动手复现的人的建议

优先用仓库自带的 uv sync 复现环境，而不是自己 pip install 一遍 pyproject.toml 里的包名——前者拿到的是作者实际跑通过的版本组合，后者可能因为下限过宽而拿到跨大版本的最新包，尤其是 openai、anthropic 这类已经发布过破坏性更新的库。

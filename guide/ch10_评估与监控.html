评估与监控：全书收官

造出了 Agent 只是一半——不能度量的东西无法改进。一个会自主行动、输出开放式文本的系统，怎么打分？

10.1两条评估路线

10.2裁判的三个正交维度

  • 答案相关性 —— 最基础的问题：答非所问吗？
  • 引用可靠性 —— 针对 Agent 特有的风险：会搜索的 Agent 也会编造来源。三连问层层递进：来源存在？来源支持论断？来源权威？
  • 需求合规性 —— 答对了但没按格式/字数/语言要求答，也算失败。

裁判提示词里最重要的一句话是强制说理：要求裁判先解释再打分，既提升判分质量，也让分数可审计。实践原则：裁判模型最好不同于被评模型（避免"自己给自己打分"），且裁判要用足够强的模型。

同一个基准贯穿全书不是偷懒，是方法论：固定度量，才能把每一次分数变化归因到具体的某个组件。而"events 记录一切"的架构决策，最终在可观测性上收获完整回报——每一次生产运行都自带可回放的审计日志。

本章要带走的几句话
  1. Agent 评估两条路线：封闭任务用精确匹配基准（GAIA），开放输出用 LLM-as-Judge。
  2. LLM-as-Judge 的关键是提示词工程：法官守则 + 强制说理；裁判模型要强、最好不同于被评模型。
  3. 三维正交评估——相关性、引用可靠性、需求合规性——单一分数掩盖问题，多维度定位问题。
  4. OPR = 通过数/总数：总值做回归门禁，按维度分解做诊断。
  5. 全书用同一个 GAIA 基准从第 2 章量到第 10 章——固定度量才能归因每个组件的贡献。

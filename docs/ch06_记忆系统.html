Chapter 06scratch_agents/memory/

给 Agent 添加记忆

第 2 章讲过：LLM 无状态，"记忆"是客户端造出来的假象。本章把这个假象工程化成三层记忆体系，分别解决三个时间尺度上的问题。

6.1执行内优化的铁律：只改视图，不动历史

三种策略从便宜到昂贵依次尝试：滑动窗口（保留头部用户问题 + 最近 N 条，最笨但零成本）；Compaction 压实——把肥大的工具结果换成一句"占位引用"（"File content from x.csv. Re-read if needed."），信息没有消失，模型需要时可以再调工具拿回来；Summarization 摘要——用 LLM 把中段历史总结成一段文字，最贵但最智能，且做增量摘要避免重复劳动。三者组合使用：先测 token 数，够用就不动，超标先上便宜的 compaction，还不够再上摘要。

6.2Human-in-the-loop 2.0：暂停与恢复

6.3长期记忆：模型隐形的"请求处理插件"

存储的是 LLM 提炼后的结构化经验（题目、方法、对错、错误分析），不是原始日志。最巧妙的设计是检索方式：给 MemoryTool 传 tool_definition=None，它就变成一个模型看不见的工具——不出现在工具清单里，但每次 LLM 调用前都会自动检索相关记忆并注入到提示词里。"工具"的概念在此升维成了请求处理插件，而不只是"模型可调用的函数"。

本章要带走的几句话
  1. 记忆分三层：执行内优化（一次 run）→ Session（跨 run）→ 向量长期记忆（跨会话），时间尺度依次增大。
  2. 上下文优化的铁律：只改 request 视图，不动 events 存储；先零成本 compaction，不够再上摘要。
  3. Human-in-the-loop 的正确姿势是"暂停 → 持久化 → 恢复"，而不是阻塞等待。
  4. 长期记忆存 LLM 提炼的结构化经验（含错误分析），提炼和查重都交给 LLM 自己判断。
  5. tool_definition=None + 请求前置钩子 = 对模型隐形、自动注入记忆的插件。

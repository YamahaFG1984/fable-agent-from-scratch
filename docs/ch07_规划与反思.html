Chapter 07scratch_agents/planning.py

规划与反思，应对复杂任务

全书最短的一章，却贡献了一个最反直觉的洞察：两个"函数体近乎什么都不做"的工具，能显著提升 Agent 的智力。全部靠提示词工程，没有一行新的框架代码。

7.1ReAct 天生短视

第 4 章的 ReAct 循环是"走一步看一步"，面对多步复杂任务会暴露四种失败模式：迷路（忘了最初目标）、重复劳动（忘了信息已查过）、死磕（一个工具反复失败还反复调）、草率收官（信息不全就急着作答）。人类专家的应对方式是"先规划、中途反思"——本章把这两个认知行为直接做成工具。

7.2空壳工具的真正价值

planning.py 
@tool
def create_tasks(tasks: List[Task]) -> str:
    """Create or update a task plan.
    WHEN TO USE: 复杂多步研究、需要综合多来源的问题
    WHEN NOT TO USE: 一次搜索能答的简单问题
    HOW TO USE: 每次重新生成整个清单并更新状态
    """
    return "\n".join(str(t) for t in tasks)
import { z } from "zod";

const TaskSchema = z.object({
  content: z.string(),
  status: z.enum(["pending", "in_progress", "completed"]),
});
type Task = z.infer<typeof TaskSchema>;

const createTasks = {
  name: "create_tasks",
  description: `Create or update a task plan.
WHEN TO USE: 复杂多步研究、需要综合多来源的问题
WHEN NOT TO USE: 一次搜索能答的简单问题
HOW TO USE: 每次重新生成整个清单并更新状态`,
  schema: z.object({ tasks: z.array(TaskSchema) }),
  execute: (tasks: Task[]) =>
    tasks
      .map((t) => `${t.status === "pending" ? "[ ]" : t.status === "in_progress" ? "[>]" : "[x]"} ${t.content}`)
      .join("\n"),
};

函数体就一行格式化，没有数据库、没有调度器、什么都不存。它的价值全靠三层机制：①强迫先想后做——要调用这个工具，模型必须先生成完整任务分解；②计划进入历史——之后每一步模型都能看到"全局地图"；③状态更新即自查——更新状态时模型被迫盘点进度。reflection 工具更极端，连格式化都算不上，就是把输入原样回显——价值全在于为了填参数，模型必须先组织一段对现状的分析，写下来的思考比隐式思考更可靠。docstring 才是本体：WHEN TO USE / WHEN NOT TO USE / HOW TO USE 三段完全是写给模型的行为指南——工具描述被推到了提示词工程的极致。

本章要带走的几句话
  1. ReAct 四大失败模式——迷路、重复劳动、死磕、草率收官——解药是移植"先规划、中反思"给 Agent。
  2. create_tasks 和 reflection 都是空壳工具：价值在于调用行为强迫模型生成结构化思考并留在历史里。
  3. 工具的 docstring 就是行为编程，WHEN NOT TO USE 同样重要——防止过度规划/反思的开销。
  4. 失败恢复 = 第 4 章"错误进历史"（让模型看见）+ 本章 reflection（让模型消化：析因换路）。
  5. 认知闭环：规划定方向 → 执行 → 反思纠偏 →（need_replan 时）重规划，纯靠两个提示词工具实现。

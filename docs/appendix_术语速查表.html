术语速查表

这些词在不同章节第一次出现，散落在各处——忘了哪个词什么意思时，回这页查一下即可，不用从头翻。按书中出现顺序排列。

LLM Agent第 1 章

把部分控制流交给 LLM 的程序：模型自己决定下一步做什么、什么时候停，而不是开发者在代码里用 if/for 写死。三要素：LLM（大脑）+ 工具（手脚）+ 循环。

上下文工程 Context Engineering第 1 章

在正确的时机把正确的信息放进 LLM 的上下文窗口的学问。Agent 失败大多不是模型不够聪明，而是该给的信息没喂到。

Harness Engineering第 1 章

模型之外、支撑 Agent 运行的一切：记忆、工具、安全执行、多 Agent 协作。公式：Agent = Model + Harness。

GAIA第 1、2 章

Meta 和 Hugging Face 发布的 Agent 评测基准，题目需要多步检索、推理、计算。全书用它作为统一的尺子，从第 2 章的裸 LLM 量到第 10 章的完整 Agent。

工具调用 Tool / Function Calling第 3 章

LLM 输出一段 JSON 声明"我想调用什么、参数是什么"，由调用方的代码负责真正执行。模型自己从不执行任何东西。

MCP Model Context Protocol第 3 章

把工具做成独立服务器进程的标准协议，任何 Agent 都能即插即用——相当于工具界的 USB 接口。

ReAct第 4 章

Reasoning + Acting：思考→行动→观察的循环。现代实现直接用原生 tool calling，不再靠正则解析文本。

ExecutionContext第 4 章

Agent 的中央状态存储，events 列表是唯一事实来源。每次调 LLM 前都从它现做一个请求视图，存储和呈现分离。

结构化输出 Structured Output第 2、4 章

用 Pydantic / zod 的 schema 约束模型输出，把 LLM 从"聊天机器人"变成程序能可靠解析的"软件组件"。

RAG 检索增强生成第 5 章

Retrieval-Augmented Generation：embedding → chunking → 向量检索，把最相关的一小撮文本放进上下文。本书里第一用途是压缩工具输出，知识库问答是次要场景。

回调 Callback（before / after）第 5 章

Agent 的中间件机制：工具执行前可拦截（如人工审批），执行后可改写（如压缩结果），None 代表不干预。

Compaction / Summarization第 6 章

两种上下文压缩策略：Compaction 把工具结果换成"占位引用"（零成本，可重放）；Summarization 用 LLM 总结旧对话（更贵，更智能）。

Session第 6 章

跨多次 run() 持久化的对话状态，让 Agent 在进程重启后仍能从上次的地方继续。

HITL Human-in-the-Loop第 5、6 章

危险操作需要人工确认。第 6 章把它从同步阻塞改成"暂停（pending_confirmation）→ 持久化 → 恢复"的异步模式。

长期记忆 Long-term Memory第 6 章

存进向量库、跨会话可检索的结构化经验（而非原始日志），让 Agent 能从以前解过的相似任务里学习。

Planning / Reflection第 7 章

两个几乎"空壳"的工具：create_tasks 强迫模型先列计划再行动；reflection 强迫模型在关键节点写下分析——价值全在于"调用的行为"本身。

CodeAct / 代码执行 Agent第 8 章

让 LLM 直接写代码并执行，而不是只能调预定义工具——行动空间从"N 个按钮"变成图灵完备的语言。

沙箱 Sandbox（E2B）第 8 章

隔离、用完即弃的云端执行环境，本质是一个远程 Jupyter kernel。LLM 生成的代码必须在这里跑，绝不能直接在主机上执行。

Agent Skills / 渐进式披露第 8 章

把"怎么用某个库"写成 SKILL.md 文档，系统提示词只放名字+一行描述，模型按需读取完整文档——扩展能力从写代码变成写文档。

Workflow（Sequential / Parallel / Loop）第 9 章

由代码写死执行顺序、多个 Agent 共享同一个 context 的编排模式；三种 Workflow 都继承 Agent，以获得可嵌套的组合律。

Agent as Tool第 9 章

把整个 Agent 包装成一个工具：子 Agent 在全新隔离的 context 里运行，调用方只拿回最终结论，中间过程不回流。

Transfer第 9 章

把整个 context（含全部历史）连同控制权一次性移交给另一个 Agent，不再返回——适合客服路由这类"分诊后专家全程接管"的场景。

A2A Agent2Agent第 9 章

把协作扩展到跨网络的协议：/.well-known/agent.json 做服务发现，JSON-RPC 的 /tasks/send 发起调用。

LLM-as-Judge第 10 章

用一个 LLM 给另一个 LLM 的输出打分，常配合"强制说理"的裁判提示词，从相关性、引用可靠性、需求合规性等正交维度评估开放式输出。

OPR Overall Pass Rate第 10 章

通过的评估数 / 总评估数，汇总成一个数字用于版本对比和 CI/CD 发版门禁；按维度分解则用于定位具体哪里出了问题。

OpenTelemetry第 10 章

生成、采集、导出可观测性数据（指标 metrics、追踪 traces、日志 logs）的开放标准，是把"Agent 线上到底发生了什么"变成可查询数据的常见选择。

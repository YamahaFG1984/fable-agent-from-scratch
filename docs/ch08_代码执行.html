用代码执行赋予 Agent 一台电脑

前七章的 Agent 只能用预先定义好的工具。本章做一次范式跃迁：让 Agent 自己写代码并执行——行动空间从"N 个固定按钮"变成整门图灵完备的语言。

8.1为什么工具调用不够用

8.2沙箱：不可信代码必须隔离

LLM 生成的代码是不可信代码——可能 rm -rf、可能泄露环境变量、可能死循环，必须隔离在用完即弃的云端微虚拟机里。E2B 沙箱本质是一个远程 Jupyter kernel：同一个沙箱内多次 run_code 共享变量，第一次定义的 data 第二次直接能用，Agent 可以多步迭代地做数据分析。生命周期用 try/finally 兜底——无论成败都销毁，不留付费资源。

8.3能力分层：从按钮到文档

Skills 的核心思想是渐进式披露（progressive disclosure）：系统提示词里只放技能名 + 一行描述（几十 token，常驻）；模型判断需要时才用 bash_tool 去读完整文档（几百 token，按需）；然后照着文档在沙箱里写代码执行（不占对话 token）。这和 Claude Code 的 skills 机制是同一个思想。

本章要带走的几句话
  1. 代码执行把行动空间从"N 个按钮"扩展成图灵完备语言：批量循环、中间数据只留沙箱、现场组合新工具。
  2. LLM 生成的代码 = 不可信代码，必须进沙箱；沙箱是持久的远程 Jupyter kernel，用 try/finally 兜底销毁。
  3. sandbox_executable 工具通过提取源码、预注册进沙箱，让 Agent 能在自己写的代码里调用你的函数。
  4. 工具从此两层：LLM 直调的普通工具 vs. 代码内调用的沙箱函数，同一份定义两处复用。
  5. Skills = 文档 + 渐进式披露：清单常驻、文档按需读、执行不占上下文。

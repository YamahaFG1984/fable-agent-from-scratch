Chapter 05scratch_agents/{rag,callbacks}.py

用 RAG 构建知识库，接入文件工具

第 4 章的 Agent 面对两类数据仍然瞎：模型没见过的私有数据，和塞不进上下文的海量数据。本章给出两把钥匙——向量检索和结构化探索——最后用回调机制把它们优雅地挂进 Agent。

5.1RAG 三件套

关键认知：embedding 捕捉的是语义而不是字面——"cat" 和 "kitten" 没有一个共同字母，但向量空间里是邻居。切块要留 overlap，否则一句话正好被切断在边界上，两个块各拿半句都检索不到。

5.2结构化检索：文件系统工具

GAIA 有一批带附件（zip / xlsx / png / mp3 / pdf）的题，纯文本 Agent 零分。数据有天然结构（目录树），导航式探索比向量检索更合适。四个工具全部体现"输出为 LLM 消费而设计"：unzip_file 解压后返回文件清单摘要；list_files 目录在前文件在后；read_file 按扩展名分派、文本带行号、表格转 markdown；read_media_file 内部再调一次多模态 LLM 处理图像/音频/PDF——主 Agent 不看像素，只拿子模型的文字结论，这是"LLM 在工具里"的委托模式，第 9 章的 Agent-as-Tool 是它的推广。

5.3回调机制：不改内核的扩展点

本章要带走的几句话
  1. RAG 三件套：embedding（语义→向量）→ chunking（固定长度+overlap）→ 余弦 top-k 检索；本质是信息过滤，不只是知识库。
  2. 本书 RAG 的第一用途是压缩工具输出，知识库问答反而是次要场景。
  3. 文件工具的设计准则：输出为 LLM 消费而格式化；路径等系统信息由代码注入，不让模型猜。
  4. read_media_file 展示"工具里再调一个 LLM"的委托模式，第 9 章会把它推广到整个 Agent。
  5. 回调 = Agent 的中间件：before 可拦截，after 可改写，None 即放行——不改内核就能加横切能力。
